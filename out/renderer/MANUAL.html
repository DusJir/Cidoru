CIdoru — User Manual

Version 1.9.1

1Introduction

CIdoru is an alternative companion application for the IDORU P-1 multi-track player. It allows you to create and manage setlists, songs, and audio routing configurations, and to export those configurations — along with your audio and MIDI files — to an SD card in the format the P-1 hardware expects.

CIdoru is available as a downloadable desktop application (Windows and Linux) and as a browser-based version. Session data in the browser version is stored in the browser's local storage. It is strongly recommended to export your session as a JSON file regularly to avoid data loss, regardless of which version you use.

⚠ Starting with version 1.9.1, the web version is provided as a demo only and is no longer actively developed. Browsers cannot reliably access your filesystem for SD card transfer and ongoing file management — the practical core of this application — so all new features and fixes now target the desktop app exclusively. Using the web version for live production work is at your own risk. See Desktop App (Electron) to download.
⚠ CIdoru is third-party software, unrelated to Idoru Live UG. For any issues or questions contact barney.estrada@bastardizer.cz — not the Idoru Live UG team.

2Concepts

Understanding these four terms is essential before using CIdoru.

Session

A session is the complete state of everything in CIdoru — all playlists, songs, mixer settings, and routing configurations. You save a session to the browser's local storage, or export it as a .json file to your disk.

Setlist (Playlist)

A setlist is an ordered collection of songs prepared for a specific occasion — for example, one gig. The P-1 hardware can hold up to 7 setlists per SD card. CIdoru enforces this limit. A setlist also stores the output volume levels and stereo pair assignments for all hardware outputs.

Song

A song is one track in a setlist. It contains references to up to six WAV audio files (F1–F6) and an optional MIDI file, plus the gain and routing settings for those files. One setlist can hold up to 40 songs. Every song in the same setlist must have a unique name.

Preset

A preset is a saved snapshot of the mixer state — routing, fader positions, mute states, and stereo links — that can be applied to a new song as a starting point. Presets do not store song metadata (name, BPM, queue behaviour) or audio file assignments.

4Playlists

Creating a playlist

Click the + button in the Playlists pane header. A modal window will appear. Enter a name and click Save.

Naming rules

Playlist names follow the P-1 naming convention: letters a–z and A–Z, digits 0–9, a space, and the symbols ! @ # $ % ^ _ = + - & ( ). Maximum 32 characters. Invalid characters are filtered out automatically as you type.

Selecting a playlist

Click on a playlist row. The Songs pane will update to show the songs belonging to that playlist. The mixer remains inactive until a song is also selected.

Editing a playlist

Click the ✎ icon on the playlist row. The same modal used for creation will appear, pre-filled with the current name.

Duplicating a playlist

Click the ⧉ icon. A copy of the playlist and all its songs is created immediately, with "copy" appended to the name. The 7-playlist limit is checked — if already at 7, an error is shown.

Reordering playlists

Use the ↑ and ↓ arrow buttons on each row. The order here matches the order in which setlists appear on the SD card.

Deleting a playlist

Click the ✕ icon. A confirmation dialog will appear warning that all songs in the playlist will also be deleted.

5Songs

Creating a song

Select a playlist first, then click the + button in the Songs pane header. The New Song window will open.

New Song window

Assign to Playlist(s) — When creating a new song you can assign it to one or more playlists simultaneously. The active playlist is pre-selected. If more than one playlist is selected, the song is duplicated into each one independently.

Start from Preset (optional) — If any presets have been saved, a dropdown appears. Selecting a preset applies its routing, fader levels, mute states, and stereo links to the new song. Audio file assignments are not copied.

Song Details:

  • Name — Required. Follows P-1 naming rules (32 characters max).
  • BPM — Tempo displayed on the P-1 screen. Visual reference only.
  • Queue — What happens when the song ends: Queue Next (waits for trigger), Play Next (auto-advances), or Loop.
  • MIDI — Optional. Filename without .mid. Use ↑ MID to browse.

Audio Files — F1 to F6:
Each slot has a mono/stereo toggle, a two-character display name (e.g. BD, SY), a filename field, and a ↑ WAV browse button. Picking a WAV file auto-fills the name, detects stereo/mono from the header, and validates sample rate and bit depth. Warnings appear below the slot if the file is not 44.1 kHz / 16-bit. The same mono/stereo toggle is also available directly on the mixer strip — see The Mixer — Classic Fader View.

Editing, duplicating, reordering, deleting

Use the ✎, ⧉, ↑/↓, and ✕ icons on each song row, same as playlists. Song order is the playback order on the P-1. The 40-song-per-playlist limit is enforced on creation and duplication.

6The Mixer — Classic Fader View

The mixer becomes active when a song is selected. It has two fader banks.

INPUT BANK (left)

The seven faders represent the audio sources: AF 01–AF 06 (WAV slots) and AUX IN (analogue input, always mono). Each fader controls the gain of that source into the currently selected output(s). The left bank is dimmed and non-interactive when no output is selected.

OUTPUT BANK (right)

The seven faders represent the hardware outputs: OUT 1–OUT 6 and PHONES. Each controls the volume of that output — these values map to setlist-level output volumes in the P-1 file. Below the strips is the M.TRIM knob: a global gain offset for the song (−20 to +20 dB). Double-click to reset to 0 dB.

Selecting an output for routing

Click a strip in the OUTPUT BANK to select it. The INPUT BANK activates. Hold Shift and click to add more outputs to the selection — moving an input fader then writes to all selected outputs simultaneously.

Stereo linking

Adjacent output pairs (OUT 1+2, OUT 3+4, OUT 5+6) can be linked using the LINK button on the even-numbered strip. When linked, both outputs share the same volume, routing values mirror automatically, and routing a source to the pair costs 2 connections.

Mono / Stereo toggle

The circle indicator at the top of each AF strip shows whether that slot is mono (single circle) or stereo (two interlocked circles). Click the indicator to switch between the two — this is the same setting available in the Song editor, just accessible directly from the strip without opening a modal. Stereo sources consume 2 connections per active routing instead of 1, so toggling a slot to stereo can affect the connections counter (see Connection Limit). AUX IN is always mono and has no toggle.

Mute

Each strip has an M button. The mute state shown on screen is not something you set directly — it is always recalculated from the strip's actual condition for the currently selected output:

  • No audio file assigned → MUTE.
  • Routing level for the currently selected output is 0 → MUTE.
  • Otherwise, MUTE follows your manual toggle (off by default).

The first two conditions are hard blocks: if either is true, the M button is shown disabled (greyed out, locked icon, no click effect) because toggling it manually would have no effect — a slot with no file or a zero-level route is always muted regardless of the manual flag. Once a file is assigned and the level is above 0, the button becomes active again and your last manual choice (or the default of unmuted) applies.

This recalculation happens automatically whenever anything relevant changes — picking a different output in the OUTPUT BANK, assigning or clearing a file, editing a cell in Matrix View, dragging a fader, or resetting a strip. You never need to manually "fix" the M indicator; it always reflects the real, current state of that channel for the output you're looking at.

Muted inputs (per the rules above) are excluded entirely from the connections count — see Connection Limit for exactly how that's calculated. Muted outputs are silenced in hardware.

Strip reset

Each audio file strip (AF 01–AF 06) has an R button next to the mute button. Clicking it resets that strip completely:

  • Removes the assigned audio file.
  • Clears the short name label back to the default.
  • Zeros the routing level to all outputs.
  • Clears any manual mute override — since there is no file, the strip shows MUTE (hard-blocked) regardless.
  • Resets the channel mode to mono.

AUX IN and all right bank strips do not have a reset button — only the six audio file slots can be reset this way. If you want to remove a file assignment without resetting all values, open Edit Song and clear the filename field manually.

File occupancy indicator

Each input strip (AF 01–AF 06) shows a small indicator below the M and ↑ buttons. A dim grey dot means no file is assigned to that slot. A green dot with the slot's two-character short name means a file is assigned. Hovering over the indicator shows a tooltip with the full filename. Click the ↑ button to assign or reassign a file.

Value readout

Each strip shows its value below the fader — dB for outputs, 0–100 for inputs in routing mode (90 ≈ unity). Double-click the readout to type a value. Double-click the rider to snap to unity.

7The Mixer — Matrix View

Click MATRIX in the toolbar to switch views. The matrix shows the full 7×7 input/output routing table as an editable grid.

  • Rows — inputs: AF 01–AF 06, AUX IN
  • Columns — outputs: HP, OUT 1–OUT 6
  • Values — 0 to 100. Zero means no routing. 90 ≈ unity gain.

Navigate cells with Tab. Linked columns are highlighted and always mirror each other.

8Routing Map

Below the mixer (in both views) is a read-only dynamic overview of all active routing connections. Each output with at least one source routed to it appears as a box showing the connected sources with their levels, colour-coded by value. Currently selected outputs are highlighted. This panel is for information only — values are changed in the fader or matrix view.

9Presets

Saving a preset

  1. Select a song with the mixer state you want to save.
  2. Click ★ PRESET in the toolbar.
  3. Enter a name and optional comment, then click Save Preset.

Presets are stored in browser local storage independently of the session — they survive loading a different session.

Applying a preset

When creating a new song, a Start from Preset dropdown appears if any presets exist. Select one to apply its routing and fader values. Audio file slots are left empty.

10Session Management

Save

Writes the session to browser local storage. The SAVE button glows amber when there are unsaved changes.

Load

Reloads the session from local storage, discarding any unsaved in-memory changes.

New Session

Resets everything to a blank state. If there are unsaved changes, a confirmation dialog warns you first. Local storage is not affected until you click Save.

Export JSON

Saves the complete session as a .json file to your downloads folder. The filename includes a timestamp.

Import JSON

Opens a file picker. Select a previously exported .json file to restore that session.

Import .idoru

Click ↑ .IDORU in the toolbar to import a session from the original Idoru application's native format. CIdoru reads the .idoru file (which is JSON) and converts it automatically:

  • Playlists and their order are preserved exactly as defined in the original session.
  • Songs F1–F6 are mapped to CIdoru audio slots. The F7 AUX/VJ channel has no equivalent and is silently skipped.
  • The routing matrix is reconstructed from the per-output, per-input routing data in the original file.
  • Output fader levels, stereo link pairs, and queue behaviour (Loop / Queue Next / Play Next) are all imported.
  • File paths from the original session are stored in the file cache automatically — if the files exist at those paths on the current machine, they will be found without relinking.

A file scan runs automatically after import. Files that are not found at their original paths appear as Missing or Unverified in the scan results — use Relink or ⌕ Choose Folder to resolve them.

ℹ The ↑ .IDORU button is only available in the desktop (Electron) version. The web version uses a standard file picker instead.
✓ Export your session as JSON after every significant editing session. Browser storage can be cleared accidentally.

11SD Card Transfer

Click ⏏ TRANSFER to write the session to an SD card. A directory picker opens — navigate to the root of the SD card and confirm. A Transfer Progress window appears immediately and streams a live log of every operation.

What gets written

CIdoru creates and maintains the following structure on the SD card:

/lists/
  session.json
  {SetlistName}/
    {SetlistName}.txt     ← setlist config
    setlist.json
    {SongName}/
      {SongName}.txt      ← song config
      song.json
      fileMap.json
      {AudioFile}.wav
      {MidiFile}.mid
/update/                  ← always present (for firmware)

Delta transfer — what actually gets copied

CIdoru compares what is already on the SD card against the current session before writing anything. The rules are:

  • Text and JSON files — written only if content has changed.
  • WAV and MIDI files — compared by file size. If the size on the SD card matches the source file, the copy is skipped. If the sizes differ (e.g. a backing track was edited and re-exported under the same name), the file is overwritten. This means a renamed-but-identical file will not be unnecessarily re-copied, and an updated file with the same name will always be detected and replaced.
  • Deleted playlists and songs — their folders are removed from the SD card automatically.

Pre-flight check

Before writing begins, CIdoru checks every required audio and MIDI file. If any file is absent from both the file cache and the SD card, the transfer is aborted and the progress log lists the missing files. Use ⌕ SCAN and Relink/Pick to resolve them first, then run Transfer again.

If a file is not in the cache but already exists on the SD card (e.g. it was picked in a previous session), CIdoru leaves it in place and notes it as "unverified" in the log. Size verification is not possible in this case because the source file is unknown. Relinking is recommended to enable full verification.

Transfer Progress window

The progress window shows a live scrolling log of every file operation. It stays open after completion so you can review the summary line at the bottom, which shows how many files were copied, skipped, or flagged with warnings. Close the window once you are done reviewing.

Do not close the application while a transfer is in progress.

ℹ Desktop version: file paths are saved to file-cache.json alongside your session whenever you click Save. Once you pick a file, its path is remembered across app restarts. You only need to re-pick a file if it has been moved, renamed, or deleted.
⚠ Web version: the browser cannot access files on disk without the user explicitly selecting them. File references are not saved between page loads — only filenames are. Re-picking via the ↑ WAV / ↑ MID buttons or the scan modal Pick buttons is required once per session. SD card transfer also requires Chrome or Edge — Firefox and Safari do not support the File System Access API.

12Firmware

Click ⬆ FIRMWARE in the toolbar to open the Firmware Manager. The behaviour differs between the web and desktop versions.

Web version

Browser security prevents downloading files from external sites programmatically. The web version shows step-by-step manual instructions. Download the .bin file from idoru.live/downloads yourself, then follow the SD card instructions in the modal.

Desktop version (Electron) — Firmware Manager

The desktop app can check for, download, and write firmware automatically. The manager is divided into three steps.

Step 1 — Get firmware

Click ⌕ Check for latest on idoru.live. CIdoru searches in two ways simultaneously: it scrapes the downloads page for known firmware links, and probes up to 15 minor versions ahead of the latest known release using fast HEAD requests. Results are sorted newest first. Click ↓ Download next to the version you want — a progress bar shows download progress. The file is saved to your local app data folder and remembered across restarts.

If you already have a .bin file on disk, click ↑ Pick .bin from disk instead. CIdoru will cache its path so Step 2 works the same way.

The status box at the top of the modal shows whether a firmware file is currently cached and which version it is. Use the ✕ Clear button to remove it if needed.

Step 2 — Write to SD card

Once a firmware file is cached, click ⏏ Select SD card & write firmware. A native folder picker opens — navigate to the root of your SD card and confirm. CIdoru will:

  • Create an update/ folder at the SD card root if it does not exist.
  • Clear any existing files inside update/ (the P-1 requires exactly one .bin file there).
  • Copy the cached .bin file into update/.

You can do this as part of a normal Transfer run or independently — firmware and session files are written separately.

Step 3 — Install on the device

  1. Make sure the SD card has at least one setlist and song (required by the P-1).
  2. With the pedal off, insert the SD card.
  3. Hold the Play footswitch down and connect power. Keep holding.
  4. Release when the firmware update message appears on the display.
  5. Unplug and replug power to restart.
ℹ The currently installed firmware version is shown at boot as SW x.x.x. The P-1 will only install a version that differs from the one currently on the device.
⚠ CIdoru cannot communicate with the P-1 via USB. Firmware is installed exclusively via the SD card method described above.

13File Scan & Relink

Click ⌕ SCAN to check all audio and MIDI file references in your session. CIdoru also runs a silent scan automatically on startup and after loading a session — it only opens the scan modal automatically if there are confirmed missing files. Unverified files are noted in the info bar without interrupting your workflow.

How file paths are remembered (desktop version)

Every time you pick a WAV or MIDI file — either via the strip buttons, the song form, or Relink — CIdoru saves the full file path to a file-cache.json stored in your application data folder. This file is updated on every Save. When you restart the app, the paths are restored automatically, so files you have picked before do not need to be re-picked.

Scan results

Each file reference is reported in one of three states:

  • Verified — the file is in the path cache and confirmed to exist on disk at the recorded path. Safe to transfer.
  • Unverified — the filename is known but no cached path is available for this session. In the desktop version this can happen if the session was imported from elsewhere or the path cache was cleared. In the web version it is the normal state before picking files. Use Pick to confirm the path, or use ⌕ Choose Folder to resolve multiple files at once.
  • Missing — the file is confirmed absent from disk at the recorded path. The file may have been moved or renamed. Use Relink or ⌕ Choose Folder to point CIdoru to the new location.

Relink and Pick — individual files

The scan modal shows a Relink button next to confirmed missing files, and a Pick button next to unverified ones. Both open a native file picker. Once you pick a file, the scan list updates immediately — you do not need to close and re-run the scan. Picked paths are saved to the file cache automatically.

Choose Folder — bulk relink

When there are multiple missing or unverified files, the ⌕ Choose Folder button appears in the scan modal footer. Click it, navigate to any folder (such as the root of your audio files library), and CIdoru will recursively scan the entire folder tree for WAV and MIDI files. It then matches files to unresolved entries by filename — the first file found with a matching name is linked automatically. All matched paths are saved to the file cache immediately. Files that do not find a match remain in the list for manual relinking.

ℹ If two files with the same name exist in different subfolders, the one found first during the recursive walk is used. If the wrong one was matched, use the individual Relink button to correct it.
✓ If you have updated a backing track file under the same name, relink it before transferring. CIdoru compares file sizes during transfer — a different-sized file with the same name will be detected and overwritten on the SD card.
✓ After resolving all flagged files, click Save to persist the updated file paths before running Transfer.

Shortcuts are active when the mixer pane has focus (click anywhere on it first).

Navigation order

AF 01 → AF 02 → … → AUX IN → OUT 1 → OUT 2 → … → PHONES → M.TRIM

Routing workflow with keyboard

  1. Press → to reach an output strip on the right bank.
  2. Press Space to select it — the input bank activates.
  3. Press ← to navigate to an input strip.
  4. Use ↑ / ↓ or the mouse wheel to set the routing level.
  5. Press M to mute/unmute the focused input.
  6. Press → to reach the next output and Space to switch target.

Nudge step sizes

  • Output faders (dB): 1 dB per step
  • Input faders in routing mode (0–100): 1 unit per step
  • M.TRIM knob: 0.5 dB per step

15Connection Limit

The P-1 hardware supports a maximum of 32 connections per song. A live counter is displayed in the status bar above the mixer — it turns amber at 28 and red at 32.

ScenarioConnections used
Mono source → mono output1
Mono source → linked stereo pair2
Mono source → headphone output2
Stereo source → any output2
Any source → headphone output2
Routing level is 0 for that output0
Source has no file assigned0 (all of that source's routes)
Source is manually muted0 (all of that source's routes)

A routing cell only counts toward the limit if it actually has a level above 0 and the source channel isn't muted. Two different things can exclude a connection: a zero level on one specific output (checked per output, doesn't affect that source's other outputs), or the channel itself having no file or being manually muted (which frees all of that channel's routes everywhere, not just the currently viewed output). This mirrors exactly what gets written to the song file at transfer time, so the on-screen counter always matches what the hardware will actually use.

✓ Muting unused sources frees their connections — the fastest way to stay within the limit during complex mixes.

16Validation Rules

All names and filenames are validated against the P-1's requirements before saving.

  • Allowed characters: a–z A–Z 0–9, space, and ! @ # $ % ^ _ = + - & ( )
  • Maximum length: 32 characters
  • WAV files: must be 44.1 kHz sample rate and 16-bit depth

Invalid characters are filtered out as you type. The Save button is disabled until all fields pass validation. WAV format warnings are shown per slot but do not block saving — the file can still be assigned, though it may not play correctly on the P-1.

Installation — Windows

Download CIdoru Setup x.x.x.exe from the CIdoru website. Run the installer. Windows will show an "Unknown Publisher" warning — click More info → Run anyway. This is expected behaviour for unsigned software; the original Idoru application behaves the same way.

Installation — Linux

Download CIdoru-x.x.x.AppImage. Make it executable and run it:

chmod +x CIdoru-x.x.x.AppImage
./CIdoru-x.x.x.AppImage

No installation required. Data is stored in ~/.config/cidoru/.

File path persistence

When you pick a WAV or MIDI file in the desktop app, CIdoru stores the full path to that file. The path survives app restarts — you do not need to re-pick files before transferring to SD card, as long as the files have not moved. If a file has moved, use ⌕ SCAN to detect and relink it.

Session storage location

  • Windows: %APPDATA%\cidoru\session.json
  • Linux: ~/.config/cidoru/session.json
  • Presets: same folder, presets.json
✓ Session and preset files are plain JSON — back them up, version-control them, or copy them between machines manually.

19Audio Transport (Preview Playback)

The Audio Transport strip sits between the mixer banks and the routing map. It lets you preview the current song's backing tracks directly in CIdoru — with all fader levels, mutes, stereo links, and M.TRIM applied in real time — without transferring to the IDORU hardware first.

What you hear

The output is a stereo downmix calculated from the OUT1–OUT6 routing columns. For each output, the matrix level and the output fader are multiplied together; stereo-linked pairs contribute to L and R channels respectively; unlinked outputs sum to both. The M.TRIM modifier knob applies as a master gain over the entire mix. Muted input slots are silenced. This is the same signal that the sound engineer would receive across all outputs — making it ideal for balancing levels before a show.

The headphone monitor output is intentionally excluded: it is a personal monitoring mix at a fixed level and does not reflect the FOH balance.

Controls

  • Progress bar — click anywhere on the bar to scrub to that position. The current time and total duration are shown at each end.
  • ⏮ Rewind — steps back 5 seconds per click.
  • ⏹ Stop — stops playback and returns to the beginning.
  • ▶ / ⏸ Play / Pause — starts playback from the current position; click again to pause in place.
  • ⏭ Fast-forward — steps forward 5 seconds per click.
  • 🔊 Monitor volume — a dedicated slider controlling the preview playback level. Completely independent of all routing faders and output levels — adjusting it does not affect the session data or what gets written to the SD card. Default is 80%.

All controls are disabled when no song is selected. If the song's files have not been loaded into the cache yet, clicking Play will attempt to load them first; if no files are available a warning message is shown.

Live level adjustment

Fader positions, mutes, and the M.TRIM knob all take effect immediately while the transport is playing — no need to stop and restart. This is the primary use case: play the full song while adjusting output levels until the stereo downmix reflects the balance you want the sound engineer to work with.

ℹ Audio playback uses the Web Audio API and runs entirely in the application — no audio is routed through the IDORU hardware during preview. The stereo output goes to your computer's default audio device.
⚠ In the web version, files must be picked in the current session before playback is possible (browser security prevents reading files from disk directly). In the desktop version, files are loaded from the persisted file cache automatically.

20Theme

CIdoru supports a dark theme (default) and a light theme. Click ☀ LIGHT / ☾ DARK in the toolbar to toggle. The preference is remembered across sessions.

Both themes support all functionality identically. The light theme is suited to bright environments such as daylit rehearsal spaces or outdoor stages.

21Automatic Updates

The desktop version of CIdoru checks for updates automatically every time it starts. The check is silent and non-blocking — the application is fully usable while it runs in the background.

If a newer version is available on GitHub, a notification bar appears below the disclaimer bar:

  • Downloading… — the update is being downloaded silently. A progress percentage is shown.
  • Ready to install — the download is complete. Click Restart & Install to apply it immediately, or simply close and reopen the application later — the update will install on next launch.

If the update check fails (e.g. no internet connection), nothing is shown and the application continues normally.

ℹ Automatic updates are only available in the packaged desktop application. The web version and development builds do not check for updates.
